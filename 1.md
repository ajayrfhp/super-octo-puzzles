## Puzzle 1: The Faulty Server (or Poisoned Wine Bottle)

### The Problem

You have 1000 servers, and exactly one has a bug that causes a crash after 24 hours. You can create "test groups" of any size. If the faulty server is in a group, a diagnostic tool reports "FAIL" after 24 hours; otherwise, it reports "PASS". All tests must run in parallel. What is the minimum number of test groups needed to guarantee you find the single faulty server in one 24-hour cycle?

### Your Thought Process

Your initial intuition was spot on. You immediately identified the core mathematical principle: **log₂(n)**. You suggested a "divide and conquer" approach, similar to a binary search, where you would test halves sequentially. You correctly calculated that for 1024 machines, this would be `log₂(1024) = 10` steps.

Your initial model was based on sequential testing (one test per day). The key challenge was adapting this insight to the constraint that all tests must run **in parallel**.

### The Solution: Bit Manipulation

The correct answer is **10 test groups**.

The solution is to use the binary representation of each server's ID as a blueprint for the test groups.

1.  **Assign Binary IDs:** Label servers 0 to 999. Convert each ID to its 10-bit binary number (since `2^10 = 1024`, which is the first power of 2 greater than or equal to 1000).
    * Server 5 = `0000000101`
    * Server 6 = `0000000110`
2.  **Create Test Groups:** Create 10 test groups, one for each bit position (Bit 0 to Bit 9).
3.  **Assign Servers:** A server is included in a test group if it has a **'1'** in that group's corresponding bit position.
4.  **Read the Results:** After 24 hours, read the results. If a group FAILS, write down a '1'. If it PASSES, write down a '0'. The resulting 10-bit binary number is the ID of the faulty server. For example, a result of `FAIL-FAIL-PASS` (`110`) from the 8-server example correctly identified server 6.

### Key Concept & Links

This puzzle is a classic example of **Bit Manipulation**. It shows how binary numbers can be used to efficiently encode information and solve problems in parallel.

## Puzzle 2: The Two Eggs Puzzle

### The Problem

You have two identical glass eggs and a 100-story building. You need to find the "threshold floor" `F`, which is the highest floor an egg can be dropped from without breaking. What is the minimum number of drops required to guarantee you find `F` in the worst-case scenario?

### Your Thought Process

You started with a very logical, linear-step strategy: dropping the first egg from floors 10, 20, 30, and so on.

You correctly analyzed the worst-case scenarios for this strategy:
* If the egg broke at floor 10, the total drops would be `1 (floor 10) + 9 (floors 1-9) = 10 drops`.
* If the egg broke at floor 100, the total drops would be `10 (floors 10-100) + 9 (floors 91-99) = 19 drops`.

You realized this was unbalanced. The key insight is that an optimal strategy must have the **same worst-case number of drops**, no matter where the threshold floor is.

### The Solution: Decreasing Intervals

The correct answer is **14 drops**.

The strategy is to make the jumps with the first egg smaller each time to balance the number of potential drops left for the second egg. If your first drop is from floor `x`, the total drops in that worst-case is `x`. To keep the total balanced, your next jump should be `x-1` floors, then `x-2`, and so on.

We need to find the smallest number `x` where the sum of the series `x + (x-1) + (x-2) + ... + 1` is at least 100.

* The formula for this sum is `x * (x+1) / 2`.
* For `x = 13`, the sum is `(13 * 14) / 2 = 91` (too low).
* For `x = 14`, the sum is `(14 * 15) / 2 = 105` (sufficient).

The dropping strategy is:
* **1st Drop:** Floor **14**
* **2nd Drop:** Floor **14 + 13 = 27**
* **3rd Drop:** Floor **27 + 12 = 39**
* ...and so on.

This ensures that no matter when the first egg breaks, the total drops needed will never exceed 14.

### Key Concept & Links

This puzzle is a classic problem in **Dynamic Programming** and **Optimization**. It's about finding an optimal strategy by minimizing the outcome in the worst-case scenario.
